# USSR Cargo Table Recognition

Библиотека для оцифровки исторических статистических таблиц СССР о межрегиональных грузопотоках по железнодорожной сети.

Проект выполняется в рамках проектной работы Яндекс для **Института истории и археологии Уральского отделения Российской академии наук (УрО РАН)**.

Исходные документы относятся преимущественно к 1940–1950-м годам и представлены фотографиями и сканами архивных материалов.

## Возможности и состояние проекта

На вход подаётся путь к ZIP с изображениями одной книги. Программа:

1. Обнаруживает заголовки строк, заголовки столбцов, числовые и пустые ячейки с помощью YOLO.
2. Распознаёт содержимое ячеек через PaddleOCR.
3. Проверяет спорные ячейки мультимодальной моделью через Alibaba Bailian или Yandex AI Studio.
4. Нормализует заголовки: оформление, aliases, сопоставление близких названий со словарём и назначение республик.
5. Проверяет уникальные заголовки текстовым запросом VLM со справочником, записывает исправления и повторно нормализует значения.
6. Строит отдельный граф ячеек каждой страницы.
7. Собирает итоговый объект BookResult.
8. Экспортирует книгу в JSON и XLSX.

Pipeline и просмотр промежуточных результатов реализованы; выполнены запуски на реальной книге из 21 страницы. Качество распознавания и размещение значений требуют сверки с исходными изображениями. Статус принятого результата не означает гарантию правильности.

## Этапы, checkpoints и повторный запуск

Порядок этапов:

~~~text
detection → ocr → review → normalization → header_review → structure → assembly → export
~~~

После успешного завершения каждого этапа, кроме export, сохраняется снимок Python-объектов. Внутри одного запуска объекты передаются в памяти; pickle используется при возобновлении и просмотре.

~~~text
outputs/<book_id>/
├── checkpoints/
│   ├── detection.pkl
│   ├── ocr.pkl
│   ├── review.pkl
│   ├── normalization.pkl
│   ├── header_review.pkl
│   └── structure.pkl
├── review_results.json          # кеш проверки изображений ячеек
├── header_review_results.json   # кеш проверки уникальных названий
├── result.pkl                   # BookResult после assembly
├── book.json
└── book.xlsx
~~~

По умолчанию `book_id` — имя ZIP без расширения. `structure.pkl` содержит графы страниц, `result.pkl` — графы и собранную таблицу. Отдельный header_report не формируется.

Начать с проверки изображений, загрузив ocr.pkl:

~~~powershell
python -u main.py ".\data\processed\1953_F1562_Op11_D4479_ячмень.zip" --start-stage review
~~~

Начать с проверки уникальных заголовков, загрузив normalization.pkl:

~~~powershell
python -u main.py ".\data\processed\1953_F1562_Op11_D4479_ячмень.zip" --start-stage header_review --log-requests
~~~

Только повторить экспорт из result.pkl:

~~~powershell
python -u main.py ".\data\processed\1953_F1562_Op11_D4479_ячмень.zip" --start-stage export
~~~

Выбранный этап и все последующие выполняются заново. Нужен готовый снимок предыдущего этапа; при его отсутствии запуск остановится. Повторный запуск удаляет снимки выбранного и последующих этапов после загрузки входного состояния. Детекция и OCR не выполняются при старте с header_review. Без `--start-stage` запуск начинается с detection.

Дополнительные параметры:

| Параметр | Назначение |
|---|---|
| `--outputs-dir` | Родительская папка результатов; book_id добавляется к ней |
| `--book-id` | Имя папки конкретной книги |
| `--log-requests` | Печатать запросы и ответы VLM; по умолчанию выключено |
| `--no-progress` | Скрыть прогресс; не отключает явно включённый лог запросов |

Снимки проверяются по отпечатку исходного ZIP. После изменения архива старые снимки могут не пройти проверку. Загружайте только доверенные локальные pickle-файлы.

## Порядок страниц в ZIP

Поддерживаются PNG, JPG/JPEG, BMP и TIF/TIFF. Страницы загружаются по одной, без распаковки ZIP на диск, в формате BGR.

**Имена изображений должны отражать фактическую последовательность страниц в книге.** Используется естественная сортировка полных имён внутри ZIP: page_2.png располагается перед page_10.png. Время создания файлов не определяет порядок.

Рекомендуемый формат:

~~~text
page_001.png
page_002.png
page_003.png
~~~

Вложенные папки также участвуют в сортировке: их названия не должны нарушать последовательность. Полные имена изображений внутри архива должны быть уникальны.

Порядок страниц необходим в том числе для обработки контекста заголовков, продолжающегося на следующей странице.

## Настройки детекции и OCR

models/config_models_det.yaml задаёт архивы YOLO, классы и параметры инференса. Три архива хранятся непосредственно в models/, без отдельных каталогов.

По умолчанию внутри архива ищется best_model.pt. Другой файл можно задать параметром weights для соответствующей модели.

Детекция выполняется на пересекающихся патчах. Обнаружения у внутренних границ патчей отбрасываются, чтобы не сохранять обрезанные ячейки. Повторы удаляются NMS и дополнительным разрешением конфликтов моделей. YOLO-модели загружаются один раз на книгу.

PaddleOCR использует PP-OCRv5_mobile_det для поиска строк и cyrillic_PP-OCRv5_mobile_rec для распознавания. OCR-модели также создаются один раз на книгу.

Для заголовков столбцов проверяются ориентации 0° и 90°. Строки заголовка собираются в одно название. Числа распознаются отдельно; десятичная запятая заменяется точкой при преобразовании значения в число.

## Проверка через VLM

models/config_review_vlm.yaml содержит провайдера, модель, имена переменных окружения, параметры запросов и размеры монтажа. `ReviewClient` использует общий Responses API для Alibaba и Яндекса.

Текущий вариант подключения — Qwen через Alibaba Bailian:

~~~yaml
provider: alibaba
model: qwen3.6-35b-a3b
api_key_env: QWEN_API_KEY
base_url_env: QWEN_BASE_URL
enable_thinking: false
batch_size: 4
timeout: 60
max_retries: 1
max_output_tokens: 4096
temperature: 0.3
montage:
  gap: 16
  label_width: 65
  max_width: 4096
  max_height: 4096
number_padding: 0
paths:
  env: .env
  output_dir: outputs
  output_name: review_results.json
header_review:
  batch_size: 20
~~~

В существующий локальный `.env` добавьте:

~~~dotenv
QWEN_API_KEY=ваш_ключ
QWEN_BASE_URL=ваш_Base_URL_из_консоли_Alibaba
~~~

Для OpenAI-совместимого подключения Alibaba Base URL заканчивается на `/compatible-mode/v1`. Используйте адрес из страницы API-ключей своего рабочего пространства. В YAML указываются имена переменных, а не секретные значения.

Для перехода на Яндекс замените настройки подключения:

~~~yaml
provider: yandex
model: deepseek-v4.1-flash/latest
api_key_env: YANDEX_CLOUD_API_KEY
base_url_env: YANDEX_CLOUD_BASE_URL
folder_id_env: YANDEX_CLOUD_FOLDER
~~~

И заполните `.env`:

~~~dotenv
YANDEX_CLOUD_API_KEY=ваш_ключ
YANDEX_CLOUD_FOLDER=идентификатор_каталога
YANDEX_CLOUD_BASE_URL=https://ai.api.cloud.yandex.net/v1
~~~

Если `.env` ещё нет, можно скопировать `.env.template` и дополнить его нужными переменными. Не перезаписывайте уже настроенный `.env`. `enable_thinking` передаётся только Alibaba. Модель должна поддерживать изображения для этапа review.

Есть два разных запроса:

- **review:** отправляет изображения только ячеек NEEDS_REVIEW, кроме EMPTY. `batch_size` задаёт число изображений в пакете. Если спорных ячеек нет, API-клиент не создаётся.
- **header_review:** отправляет уникальные непустые названия заголовков строк и столбцов текстом, вместе со справочником. `header_review.batch_size` задаёт число названий в пакете. Ответ содержит только исправления `номер<TAB>название` либо `OK`; статус для каждого названия не требуется. После проверки формата исправления записываются в Cell и повторно вызывается normalize_book с контекстными aliases.

Изображения и текст отправляются во внешний API. Успешные пакеты кешируются отдельно для каждого вида запроса. Ключи кеша учитывают модель, промпт и параметры; смена этих данных может потребовать новых запросов.

Ошибка API или некорректный ответ останавливает этап, но успешные пакеты остаются в кеше. Для продолжения используйте `--start-stage review` или `--start-stage header_review`. Снимок этапа появляется после его полного завершения, кеш — после каждого успешного пакета. Если checkpoint ещё не создан, визуализация этого этапа недоступна.

## Справочник заголовков

header_dictionary.yaml находится в корне проекта:

- aliases — подтверждённые исправления названий;
- contextual_aliases — изменения для конкретной структуры таблицы;
- republic_regions — соответствие республик и регионов;
- service_headers — допустимые служебные заголовки, например «Всего прибыло».

Нормализация обрабатывает только заголовки RECOGNIZED. Сначала исправляется оформление и применяются aliases, затем выполняется осторожное сопоставление близких названий со словарём. При близких конкурирующих вариантах значение остаётся без замены. Числовые ячейки и исходный ocr_value не изменяются.

Контекстные замены выключены по умолчанию в прямом вызове normalize_book; текущий header_review включает существующий параметр `use_contextual_aliases=True` при повторном проходе. Это, например, приводит «Аджарская АССР» к «б) Аджарская АССР» для структуры этой книги.

Справочник перенесён из старого ноутбука и относится к историческим материалам проекта. Для книг другого периода нужно проверить состав регионов и названия. Исторические названия современными автоматически не заменяются.

## Содержимое результатов

### JSON

book.json содержит все ячейки, связи графов страниц, общую матрицу, названия осей, источники значений и причины проверки.

Идентификатор ячейки уникален внутри страницы. Для всей книги используется пара (page_name, cell_id).

В матрице null может означать пустую ячейку, отсутствие найденного источника или конфликт. Различие определяется по positions и исходным records, а не только по values. Непривязанные ячейки сохраняются, а не удаляются.

review_results.json содержит только ответы VLM, а не все ячейки. batch_total_tokens относится к целому пакету и повторяется в его записях; суммировать его по ячейкам нельзя.

### XLSX

book.xlsx содержит два листа:

- «Общая таблица» — объединённая таблица книги;
- «Проверка» — спорные, конфликтующие и непривязанные записи с причинами.

Жёлтым отмечены позиции, требующие проверки. Красным и надписью «КОНФЛИКТ» — позиции с разными значениями. Конфликт не разрешается выбором первого результата: все источники сохраняются в JSON.

Ноль сохраняется как число. EMPTY не превращается в ноль. Числовые гипотезы, оставшиеся текстом, сохраняются для проверки.

## Модель данных и обработка

Cell хранит bbox = (x, y, width, height), тип ячейки, результаты детекции, исходный OCR-текст, обработанное значение, статус и сведения о модели.

PageGraph хранит ячейки одной страницы и связи left/right/up/down. Графы строятся после распознавания и нормализации; общий граф книги не создаётся. EMPTY и NEEDS_REVIEW остаются в графе, поскольку участвуют в геометрии таблицы.

ocr_value сохраняет исходный текст PaddleOCR. recognized_value хранит текущую гипотезу с учётом VLM и нормализации. Для VLM recognition_confidence используется None.

Статусы:

- RECOGNIZED — принятая автоматическая гипотеза;
- NEEDS_REVIEW — требуется дополнительная проверка.

Основной запуск через библиотеку:

~~~python
from src import run_pipeline

paths = run_pipeline(zip_path, start_stage="header_review")
~~~

`run_pipeline` управляет порядком этапов и сохранением снимков. Прямой вызов алгоритмов, например `normalize_book`, меняет переданные объекты в памяти и сам не создаёт checkpoint. Для просмотра используется `stage="result"` (или `"assembly"`), а для запуска сборки — `start_stage="assembly"`.

## Визуализация сохранённых результатов в notebook

Методы загружают выбранный checkpoint и исходные изображения из ZIP. Они не запускают OCR, VLM или pipeline и не изменяют сохранённые снимки. После замены файлов библиотеки перезапустите ядро notebook.

### Подготовка

~~~python
import sys
from pathlib import Path

PROJECT = Path(r"D:\projects\ussr-ocr-table")
sys.path.insert(0, str(PROJECT))

from src.visualization import show_book_stage
from src.cell_inspection import show_cells_stage, show_unique_headers
from src.image_io import list_pages

BOOK = PROJECT / "data" / "processed" / "1953_F1562_Op11_D4479_ячмень.zip"
PAGE = list_pages(BOOK)[0]  # Точное имя первой страницы внутри ZIP
~~~

Выберите ядро `D:\projects\ussr-ocr-table\.venv\Scripts\python.exe`. Проверить выбор можно через `print(sys.executable)`.

Доступные `stage`: `detection`, `ocr`, `review`, `normalization`, `header_review`, `structure`, `result`. Для result используется result.pkl, для остальных — checkpoints/<stage>.pkl. `assembly` — альтернативное имя result; для `export` отдельного снимка нет.

### Страницы и графы: show_book_stage

Показать все страницы после детекции, без значений и ID:

~~~python
show_book_stage(
    book=BOOK,
    stage="detection",
    show_values=False,
    show_ids=False,
);
~~~

Показать одну страницу после исправлений заголовков:

~~~python
show_book_stage(
    book=BOOK,
    stage="header_review",
    page=PAGE,
    show_values=True,
    show_ids=True,
);
~~~

Показать граф поверх исходной страницы:

~~~python
show_book_stage(
    book=BOOK,
    stage="structure",  # Можно также "result"
    page=PAGE,
    show_graph=True,
    show_boxes=False,
    show_ids=False,
    show_values=False,
);
~~~

Рёбра left/right — синие, up/down — красные. Узлы остаются видны. Граф загружается из снимка и не пересчитывается. При `show_graph=True` контуры bbox по умолчанию скрыты; `show_boxes=True` возвращает их. Граф доступен только для structure и result/assembly.

Основные параметры:

| Параметр | Значение |
|---|---|
| `page=None` | Все страницы; строка выбирает точное имя страницы из ZIP |
| `cell_ids=None` | Все ячейки; `27` — один ID, `[27, 941]` — несколько |
| `show_values=False` | Показывать текущие значения; для страниц есть fallback к ocr_value |
| `show_ids=True` | Показывать номера ячеек |
| `show_boxes=None` | Рамки видны без графа и скрыты при показе графа |
| `show_graph=False` | Показывать сохранённые рёбра графа |
| `figsize=None`, `dpi=120` | Размер и разрешение изображения |
| `save_dir=None` | Папка для PNG; по умолчанию изображения не сохраняются |
| `show=True` | Выводить страницы в notebook |

Для графа с `cell_ids` отображаются рёбра только между выбранными узлами. ID уникален внутри страницы: без `page` одинаковые ID выбираются на всех страницах.

Сохранить все страницы графа в PNG без вывода:

~~~python
saved = show_book_stage(
    book=BOOK,
    stage="structure",
    show_graph=True,
    show_ids=False,
    save_dir=PROJECT / "outputs" / BOOK.stem / "inspection" / "structure",
    show=False,
)
~~~

Возвращается список сохранённых путей; без сохранения — пустой список. При `show=False` необходимо задать `save_dir`.

### Ячейки: show_cells_stage

Выводятся строки: слева вырезка bbox, в центре текущее recognized_value, справа ID, модель, статус и другие сведения. Если значения нет, показывается «Не было распознано». Это отсутствие текущего значения, а не обязательно отсутствие попытки OCR.

Все ячейки одной страницы:

~~~python
rows = show_cells_stage(book=BOOK, stage="ocr", page=PAGE)
~~~

Все ячейки книги — вызов без page и остальных фильтров. Такой HTML может быть большим.

Выбранные ячейки:

~~~python
rows = show_cells_stage(
    book=BOOK,
    stage="header_review",
    page=PAGE,
    cell_ids=[27, 941],
)
~~~

Заголовки строк и столбцов в диапазоне ID:

~~~python
rows = show_cells_stage(
    book=BOOK,
    stage="header_review",
    page=PAGE,
    cell_types=["row_header", "column_header"],
    cell_range=(0, 1600),
)
~~~

Типы: `row_header`, `column_header`, `value`, `empty`. Можно передать один тип строкой, например `cell_types="value"`. Диапазон `cell_range` включительный, применяется к ID, а не к порядковым номерам в списке. Все заданные фильтры действуют одновременно.

Ячейки, требующие проверки:

~~~python
rows = show_cells_stage(
    book=BOOK,
    stage="header_review",
    recognition_status="needs_review",
)
~~~

Принятые результаты выбранной модели:

~~~python
rows = show_cells_stage(
    book=BOOK,
    stage="header_review",
    recognition_status="recognized",
    recognition_models="qwen3.6-35b-a3b",
)
~~~

Фильтр модели сравнивает точное recognition_model. Для Яндекса значение имеет вид `gpt://<folder>/<model>`. После текстового исправления заголовка здесь также записывается модель VLM: фильтр не различает проверку картинки и проверку названия. Пустой ответ VLM может оставлять прежнюю модель, поэтому этот фильтр не показывает все попытки обращения к VLM.

Для `recognition_status` и `recognition_models` можно передать строку или список. Сохранить выбранные строки в самостоятельный HTML с встроенными изображениями:

~~~python
rows = show_cells_stage(
    book=BOOK,
    stage="header_review",
    page=PAGE,
    save_path=PROJECT / "outputs" / BOOK.stem / "inspection" / "cells.html",
    show=False,
)
~~~

HTML открывается в браузере. Возвращается список метаданных ячеек; присваивание `rows = ...` предотвращает дополнительный вывод списка в notebook. При `show=False` необходимо указать `save_path`.

### Уникальные заголовки: show_unique_headers

После исправлений VLM и повторной нормализации:

~~~python
headers = show_unique_headers(book=BOOK, stage="header_review")
~~~

Выводятся два отдельных списка, без пустых значений. Результат доступен программно:

~~~python
row_names = headers["row_header"]
column_names = headers["column_header"]
~~~

Для сравнения со снимком до проверки VLM используйте `stage="normalization"`. Можно задать `page=PAGE`, `cell_ids=27` или список ID. `show=False` возвращает списки без печати. Совпадения названий между строками и столбцами допустимы.

Все три метода принимают `outputs_dir` и `book_id`. Если pipeline запускался с нестандартной папкой или именем книги, передайте те же значения:

~~~python
headers = show_unique_headers(
    book=BOOK,
    stage="header_review",
    outputs_dir=PROJECT / "other_outputs",
    book_id="my_book",
    show=False,
)
~~~

`outputs_dir` — родительская папка, book_id добавляется к ней. Настройки просмотра по умолчанию не сохраняют изображения или HTML.

## Особенности сборки общей таблицы

Заголовки ищутся обходом графа: строка — влево, столбец — вверх. Если ближайший заголовок отсутствует или неоднозначен, значение не размещается произвольно; источник остаётся в результатах с причиной проверки.

Страницы объединяются по названию и республике для каждой оси. Совпадающие значения не суммируются. Повторные позиции внутри одной страницы отмечаются для проверки.

Если одинаковые подписи имеют разный смысл внутри одной республики, их нужно дополнительно уточнить: текущий ключ объединения не различает такую иерархию.

Для «Всего по республике» используется контекст справа или на следующей странице. Это правило зависит от структуры книги. Геометрические допуски графа и справочник требуют проверки при переходе на новые документы.

## Данные и секреты в Git

Не добавляйте в репозиторий ключи, входные данные, веса и результаты обработки. В .gitignore должны быть правила:

~~~gitignore
.env
.env.*
!.env.template
.venv/
data/
outputs/
*.zip
*.pt
*.pth
*.onnx
~~~

.env.template, YAML-конфигурации и header_dictionary.yaml хранятся в репозитории без API-ключей. Правило !.env.template разрешает хранить шаблон, несмотря на исключение .env.*. Архивы моделей предоставляются отдельно.
