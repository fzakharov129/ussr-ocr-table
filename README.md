# USSR Cargo Table Recognition

Библиотека для оцифровки исторических статистических таблиц СССР о межрегиональных грузопотоках по железнодорожной сети.

Проект выполняется в рамках проектной работы Яндекс для **Института истории и археологии Уральского отделения Российской академии наук (УрО РАН)**.

Исходные документы относятся преимущественно к 1940–1950-м годам и представлены фотографиями и сканами архивных материалов.

## Быстрый запуск

Пример ниже рассчитан на Windows и PowerShell. Выполняйте команды из корня проекта; путь к нему и имя архива книги замените на свои.

1. Создайте окружение и установите зависимости:

```powershell
cd D:\projects\ussr-ocr-table
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Для просмотра результатов в ноутбуке дополнительно установите `matplotlib`, `ipython` и `ipykernel`, а затем выберите ядро из `.venv`:

```powershell
python -m pip install matplotlib ipython ipykernel
```

2. Подготовьте модели в `models/`. Веса и архивы поставляются отдельно от кода:

```text
models/
├── yolo_cell_detection_headers_v2.zip
├── yolo_cell_detection_value_v2.zip
├── yolo_empty_cell_detection_v2.zip
├── PaddleOCR-3.3.0.zip
├── finetuned_paddle_v5_headers_v2/  или  finetuned_paddle_v5_headers_v2.zip
└── finetuned_paddle_v5_values_v2/   или  finetuned_paddle_v5_values_v2.zip
```

Скачайте исходный архив [PaddleOCR v3.3.0](https://github.com/PaddlePaddle/PaddleOCR/releases/tag/v3.3.0): в разделе Assets выберите **Source code (zip)**. Сохраните архив в `models/PaddleOCR-3.3.0.zip`; если браузер дал ему другое имя, переименуйте его. Распаковывать архив вручную не нужно.

Каждый комплект распознавания должен содержать `best_model.pdparams`, `inference_config.yaml` и `ppocrv5_cyrillic_dict.txt`. Если присутствуют и папка, и одноимённый ZIP, автоматически выбирается ZIP. Детектор строк `PP-OCRv5_mobile_det` загружается средствами PaddleOCR и может потребовать подключение к сети при первом запуске.

3. Настройте Yandex AI Studio. Если файла `.env` ещё нет, создайте его из шаблона:

```powershell
Copy-Item .env.template .env
```

Впишите в `.env` собственные `YANDEX_CLOUD_API_KEY` и `YANDEX_CLOUD_FOLDER`. Файл с ключом не добавляется в Git. Для этапов проверки нужна доступная модель Qwen и подключение к Yandex AI Studio; запросы могут тарифицироваться.

4. Подготовьте ZIP с изображениями одной книги и запустите обработку:

```powershell
python -u main.py "D:\data\book.zip"
```

Поддерживаются JPG, PNG, BMP и TIFF. Имена страниц внутри ZIP должны отражать их последовательность. Архив читается без распаковки на диск.

5. Откройте `outputs/book/book.xlsx`. В `outputs/book/` также сохраняются `book.json` и промежуточные результаты. На листе «Проверка» перечислены сомнительные заголовки и значения; конфликтные и требующие проверки позиции выделены в основной таблице. Результат необходимо сверять с исходными изображениями.

Для запуска из Python или ноутбука, открытого в окружении проекта:

```python
from src import run_pipeline

paths = run_pipeline(r"D:\data\book.zip")
print(paths)
```

В проекте пока не настроена установка собственного пакета через `pip install .`; этот пример использует модули из корня проекта. Параметры отдельных этапов, просмотр графов и подготовка данных описаны ниже.

## Возможности и состояние проекта

На вход подаётся путь к ZIP с изображениями одной книги. Программа:

1. Обнаруживает заголовки строк, заголовки столбцов, числовые и пустые ячейки с помощью YOLO.
2. Распознаёт содержимое ячеек через PaddleOCR.
3. Проверяет спорные ячейки мультимодальной моделью через Yandex AI Studio.
4. Нормализует заголовки: оформление, aliases, сопоставление близких названий со словарём и назначение республик.
5. Проверяет уникальные заголовки текстовым запросом VLM со справочником, записывает исправления и повторно нормализует значения.
6. Строит отдельный граф ячеек каждой страницы.
7. Формирует таблицы страниц.
8. Сопоставляет последовательности заголовков и определяет контекст итоговых столбцов.
9. Собирает итоговый объект BookResult.
10. Экспортирует книгу в JSON и XLSX.

Pipeline и просмотр промежуточных результатов реализованы; выполнены запуски на реальной книге из 21 страницы. Качество распознавания и размещение значений требуют сверки с исходными изображениями. Статус принятого результата не означает гарантию правильности.

## Этапы, checkpoints и повторный запуск

Порядок этапов:

~~~text
detection → ocr → review → normalization → header_review → structure → page_tables → sequence_review → republic_headers → assembly → export
~~~

После успешного завершения каждого этапа, кроме export, сохраняется снимок Python-объектов. Внутри одного запуска объекты передаются в памяти; pickle используется при возобновлении и просмотре.

~~~text
outputs/<book_id>/
├── checkpoints/
│   ├── detection.pkl
│   ├── ocr.pkl
│   ├── review.pkl
│   ├── normalization.pkl
│   ├── header_review.pkl
│   ├── structure.pkl
│   ├── page_tables.pkl
│   ├── sequence_review.pkl
│   └── republic_headers.pkl
├── review_results.json          # кеш проверки изображений ячеек
├── header_review_results.json   # кеш проверки уникальных названий
├── result.pkl                   # BookResult после assembly
├── book.json
├── book.xlsx
└── pages_xlsx/                  # таблицы отдельных страниц
    ├── 001_<имя_страницы>.xlsx
    └── ...
~~~

По умолчанию `book_id` — имя ZIP без расширения. `structure.pkl` содержит графы страниц, следующие checkpoints — таблицы страниц и результаты контекстной проверки, `result.pkl` — собранную таблицу. Отдельный header_report не формируется.

Начать с проверки изображений, загрузив ocr.pkl:

~~~powershell
python -u main.py ".\data\processed\1953_F1562_Op11_D4479_ячмень.zip" --start-stage review
~~~

Начать с проверки уникальных заголовков, загрузив normalization.pkl:

~~~powershell
python -u main.py ".\data\processed\1953_F1562_Op11_D4479_ячмень.zip" --start-stage header_review --log-requests
~~~

Только повторить экспорт из result.pkl:

~~~powershell
python -u main.py ".\data\processed\1953_F1562_Op11_D4479_ячмень.zip" --start-stage export
~~~

Можно остановиться после выбранного этапа включительно:

~~~powershell
python -u main.py ".\data\processed\1953_F1562_Op11_D4479_ячмень.zip" --end-stage detection
python -u main.py ".\data\processed\1953_F1562_Op11_D4479_ячмень.zip" --start-stage ocr --end-stage ocr
~~~

Для вызова из Python используйте `run_pipeline(zip_path, start_stage="ocr", end_stage="ocr")`. При остановке до export результат содержит `checkpoint` — путь к сохранённому снимку; после export возвращаются пути `json`, `xlsx` и `pages_dir`. По умолчанию конечный этап — export.

Выполняются этапы от `--start-stage` до `--end-stage` включительно. Конечный этап не может быть раньше начального. Нужен готовый снимок предыдущего этапа; при его отсутствии запуск остановится. Повторный запуск удаляет снимки выбранного и последующих этапов после загрузки входного состояния, даже при остановке до export. Детекция и OCR не выполняются при старте с header_review. Без `--start-stage` запуск начинается с detection.

Дополнительные параметры:

| Параметр | Назначение |
|---|---|
| `--end-stage` | Последний выполняемый этап включительно; по умолчанию export |
| `--outputs-dir` | Родительская папка результатов; book_id добавляется к ней |
| `--book-id` | Имя папки конкретной книги |
| `--log-requests` | Печатать запросы и ответы VLM; по умолчанию выключено |
| `--no-progress` | Скрыть прогресс; не отключает явно включённый лог запросов |

Снимки проверяются по отпечатку исходного ZIP. После изменения архива старые снимки могут не пройти проверку. Загружайте только доверенные локальные pickle-файлы.

## Таблицы страниц и проверка контекста

После графов этап `page_tables` формирует отдельные таблицы страниц, сохраняя идентификаторы `(page_name, cell_id)`. Этап `sequence_review` сравнивает последовательности заголовков, исправляет названия при поддержке согласованного окружения и сохраняет исходный вариант и подтверждающие ячейки. Неоднозначные варианты отмечаются для проверки. Этап `republic_headers` определяет республику для итоговых столбцов по соседним подтверждённым заголовкам на той же странице. При противоречии или недостатке данных итоговый столбец остаётся отдельным и помечается для проверки.

```powershell
python -u main.py "D:\data\book.zip" --start-stage page_tables --end-stage republic_headers
python -u main.py "D:\data\book.zip" --start-stage assembly
```

Для первой команды нужен `structure.pkl`, для второй — `republic_headers.pkl`. Каждый этап сохраняет собственный checkpoint; при повторном выполнении последующие контрольные точки сбрасываются. В `visualize_book_library.ipynb` можно выбрать `PAGE_INDEX` и `TABLE_STAGE`, чтобы посмотреть таблицу до проверки, после сопоставления и после добавления контекста республики. Итоговый JSON содержит исправления, предложения и обоснования контекста.

### Выгрузка и проверка таблиц страниц

При этапе `export` программа сохраняет `book.xlsx` и отдельный XLSX для каждой страницы непосредственно в `outputs/<book_id>/pages_xlsx/`. В каждом файле два листа: «Общая таблица» с данными страницы и «Проверка» с замечаниями. Жёлтым выделены заголовки и ячейки, требующие проверки, красным — конфликтующие значения. Проверяйте замечания по исходному изображению: причина может относиться к заголовку или его контексту, а не к самому числу.

Файлы с совпадающими именами при следующем экспорте **перезаписываются**. Закройте их в Excel перед запуском; если нужны ручные изменения, сохраните копии в другом месте. Старые подпапки с датами автоматически не удаляются. Изменения, внесённые в XLSX, **не считываются** при сборке книги: общая таблица строится из сохранённых данных страниц, а XLSX служат для просмотра.

Повторно сформировать общую книгу и таблицы страниц из `result.pkl`, без запуска распознавания и VLM:

```powershell
cd D:\projects\ussr-ocr-table
$book = "1942_F1562_Op11_D1249_руда_марганцевая"
$zip = ".\data\processed\$book.zip"
& .\.venv\Scripts\python.exe -u .\main.py $zip --start-stage export
```

Чтобы пересобрать общую таблицу из сохранённого `republic_headers.pkl`, начните с `--start-stage assembly`. Для применения изменений справочника или логики более ранних этапов выберите соответствующий этап; экспорт сам по себе не пересчитывает распознавание и контекст. При повторном запуске VLM может использовать сохранённые `review_results.json` и `header_review_results.json`.

Пустые ячейки остаются в графе для построения связей, но при сборке таблиц для них не создаются записи значений и не ищется позиция. Данные значений привязываются к заголовкам, если связи определены однозначно. Источники заголовков в общей таблице сохраняются как пары `page_name` и `cell_id`, поэтому можно найти страницы и исходные ячейки.

## Порядок страниц в ZIP

Поддерживаются PNG, JPG/JPEG, BMP и TIF/TIFF. Страницы загружаются по одной, без распаковки ZIP на диск, в формате BGR.

**Имена изображений должны отражать фактическую последовательность страниц в книге.** Используется естественная сортировка полных имён внутри ZIP: page_2.png располагается перед page_10.png. Время создания файлов не определяет порядок.

Рекомендуемый формат:

~~~text
page_001.png
page_002.png
page_003.png
~~~

Вложенные папки также участвуют в сортировке: их названия не должны нарушать последовательность. Полные имена изображений внутри архива должны быть уникальны.

Порядок страниц важен для последовательного просмотра и сопоставления данных книги.

## Настройки детекции и OCR

models/config_models_det.yaml задаёт архивы YOLO, классы и параметры инференса. Три архива хранятся непосредственно в models/, без отдельных каталогов.

По умолчанию внутри архива ищется best_model.pt. Другой файл можно задать параметром weights для соответствующей модели.

Детекция выполняется на пересекающихся патчах. Обнаружения у внутренних границ патчей отбрасываются, чтобы не сохранять обрезанные ячейки. Повторы удаляются NMS и дополнительным разрешением конфликтов моделей. YOLO-модели загружаются один раз на книгу.

PaddleOCR использует PP-OCRv5_mobile_det для поиска строк и дообученные распознаватели PP-OCRv5 v2 отдельно для заголовков и чисел. OCR-модели создаются один раз на книгу.

Для заголовков столбцов проверяются ориентации 0° и 90°. Строки заголовка собираются в одно название. Числа распознаются отдельно; десятичная запятая заменяется точкой при преобразовании значения в число.

## Проверка через VLM

`models/config_review_vlm.yaml` содержит настройки Qwen 3.6 через Yandex AI Studio. `ReviewClient` отправляет запросы через Responses API. В YAML указаны имена переменных окружения, секретные значения хранятся в `.env`:

~~~dotenv
YANDEX_CLOUD_API_KEY=ваш_ключ
YANDEX_CLOUD_FOLDER=идентификатор_каталога
YANDEX_CLOUD_BASE_URL=https://ai.api.cloud.yandex.net/v1
~~~

Если `.env` ещё нет, скопируйте `.env.template` и дополните его. Существующий `.env` не перезаписывайте. Модель должна поддерживать изображения для этапа review.

Режим рассуждений настраивается отдельно: `reasoning_enabled: false` для review и `header_review.reasoning_enabled: false` для header_review. Значение `false` передаёт `reasoning={"effort": "none"}`; значение `true` использует режим модели по умолчанию. Изменение настройки учитывается в ключах кеша.

Есть два разных запроса:

- **review:** отправляет изображения только ячеек NEEDS_REVIEW, кроме EMPTY. `batch_size` задаёт число изображений в пакете. Если спорных ячеек нет, API-клиент не создаётся.
- **header_review:** отправляет уникальные непустые названия заголовков строк и столбцов текстом, вместе со справочником. `header_review.batch_size` задаёт число названий в пакете. Ответ содержит только исправления `номер<TAB>название` либо `OK`; статус для каждого названия не требуется. Ответ нормализуется и проверяется по справочнику; неизвестные или неоднозначные исправления помечаются для ручной проверки. Маркеры вложенности сохраняются. Затем повторно вызывается normalize_book с контекстными aliases.

Изображения и текст отправляются во внешний API. Успешные пакеты кешируются отдельно для каждого вида запроса. Ключи кеша учитывают модель, промпт и параметры; смена этих данных может потребовать новых запросов.

Некорректный ответ или временная ошибка API повторяется до `max_attempts` раз (по умолчанию 5 попыток, включая первую); автоматические повторы SDK отключены. Между попытками предусмотрена пауза. Постоянные ошибки API и исчерпание попыток останавливают этап, но успешные пакеты остаются в кеше. Для продолжения используйте `--start-stage review` или `--start-stage header_review`. Снимок этапа появляется после его полного завершения, кеш — после каждого успешного пакета. Если checkpoint ещё не создан, визуализация этого этапа недоступна.

## Справочник заголовков

header_dictionary.yaml находится в корне проекта:

- aliases — подтверждённые исправления названий;
- contextual_aliases — изменения для конкретной структуры таблицы;
- republic_regions — соответствие республик и регионов;
- service_headers — допустимые служебные заголовки, например «Всего прибыло».

Нормализация обрабатывает только заголовки RECOGNIZED. Сначала исправляется оформление и применяются aliases, затем выполняется осторожное сопоставление близких названий со словарём. При близких конкурирующих вариантах значение остаётся без замены. Числовые ячейки и исходный ocr_value не изменяются.

Контекстные замены выключены по умолчанию в прямом вызове normalize_book; текущий header_review включает существующий параметр `use_contextual_aliases=True` при повторном проходе. Это, например, приводит «Аджарская АССР» к «б) Аджарская АССР» для структуры этой книги.

Справочник перенесён из старого ноутбука и относится к историческим материалам проекта. Для книг другого периода нужно проверить состав регионов и названия. Исторические названия современными автоматически не заменяются.

## Содержимое результатов

### JSON

book.json содержит все ячейки, связи графов страниц, общую матрицу, названия осей, источники значений и причины проверки.

Идентификатор ячейки уникален внутри страницы. Для всей книги используется пара (page_name, cell_id).

В матрице null может означать пустую ячейку, отсутствие найденного источника или конфликт. Различие определяется по positions и исходным records, а не только по values. Непривязанные ячейки сохраняются, а не удаляются.

review_results.json содержит только ответы VLM, а не все ячейки. batch_total_tokens относится к целому пакету и повторяется в его записях; суммировать его по ячейкам нельзя.

### XLSX

book.xlsx содержит два листа:

- «Общая таблица» — объединённая таблица книги;
- «Проверка» — спорные, конфликтующие и непривязанные записи с причинами.

Жёлтым отмечены заголовки и позиции, требующие проверки. Красным и надписью «КОНФЛИКТ» — позиции с разными значениями. Конфликт не разрешается выбором первого результата: все источники сохраняются в JSON.

Ноль сохраняется как число. EMPTY не превращается в ноль. Числовые гипотезы, оставшиеся текстом, сохраняются для проверки.

## Модель данных и обработка

Cell хранит bbox = (x, y, width, height), тип ячейки, результаты детекции, исходный OCR-текст, обработанное значение, статус и сведения о модели.

PageGraph хранит ячейки одной страницы и связи left/right/up/down. Графы строятся после распознавания и нормализации; общий граф книги не создаётся. EMPTY и NEEDS_REVIEW остаются в графе, поскольку участвуют в геометрии таблицы.

ocr_value сохраняет исходный текст PaddleOCR. recognized_value хранит текущую гипотезу с учётом VLM и нормализации. Для VLM recognition_confidence используется None.

Статусы:

- RECOGNIZED — принятая автоматическая гипотеза;
- NEEDS_REVIEW — требуется дополнительная проверка.

Основной запуск через библиотеку:

~~~python
from src import run_pipeline

paths = run_pipeline(zip_path, start_stage="header_review")
~~~

`run_pipeline` управляет порядком этапов и сохранением снимков. Прямой вызов алгоритмов, например `normalize_book`, меняет переданные объекты в памяти и сам не создаёт checkpoint. Для просмотра используется `stage="result"` (или `"assembly"`), а для запуска сборки — `start_stage="assembly"`.

## Особенности сборки общей таблицы

Заголовки ищутся обходом графа: строка — влево, столбец — вверх. Если ближайший заголовок отсутствует или неоднозначен, значение не размещается произвольно; источник остаётся в результатах с причиной проверки.

Страницы объединяются по названию и республике для каждой оси. Совпадающие значения не суммируются. Повторные позиции внутри одной страницы отмечаются для проверки.

Если одинаковые подписи имеют разный смысл внутри одной республики, их нужно дополнительно уточнить: текущий ключ объединения не различает такую иерархию.

Для «Всего по республике» используется группа заголовков справа на той же странице. Для определения республики нужны как минимум два согласованных заголовка; при противоречии или недостатке данных название остаётся на проверке. Геометрические допуски графа и справочник требуют проверки при переходе на новые документы.

## Дообученные распознаватели PP-OCRv5

Основной OCR автоматически использует `best_model.pdparams` из папок:

- `models/finetuned_paddle_v5_headers_v2` — заголовки;
- `models/finetuned_paddle_v5_values_v2` — числовые значения.

В каждой папке нужны `inference_config.yaml`, `ppocrv5_cyrillic_dict.txt` и обученные
веса. История и метрики для распознавания не требуются. Код загрузки находится в
`src/paddle_recognition.py`; скрипты из папок моделей не исполняются.
Поддерживаются обучаемые `.pdparams`, inference-экспорт не нужен.

Исходники архитектуры PaddleOCR 3.3.0 берутся из локального
`models/PaddleOCR-3.3.0.zip` или `PaddleOCR-3.3.0-runtime.zip` в папке распознавателя.
В `models/.runtime/PaddleOCR-3.3.0` один раз распаковывается только каталог ppocr;
этот каталог общий для headers и values. Сеть для загрузки обученных весов и
исходников не используется. Отдельный стандартный детектор строк продолжает
загружаться через PaddleOCR; его собственные правила кеширования не менялись.

Обе дообученные модели обязательны. Если весов values пока нет, добавьте их в
соответствующую папку перед запуском. При отсутствии файлов возникает ошибка
с точным путём; автоматической подмены стандартной моделью нет.

```python
from src.ocr import recognize_book

result = recognize_book(book_zip, cells_by_page, device="cpu")

# При необходимости задать веса явно:
result = recognize_book(
    book_zip,
    cells_by_page,
    device="cpu",
    headers_model_dir="models/finetuned_paddle_v5_headers_v2",
    values_model_dir="models/finetuned_paddle_v5_values_v2",
)
```

`use_finetuned=False` явно возвращает стандартные распознаватели.
Для последних весов укажите `recognition_weights="last_model.pdparams"`.
В Cell сохраняется имя фактически использованной модели для соответствующего типа.
Ограничения символов берутся из inference_config: для values — цифры и точка.
Нормализация совпадает с ноутбуками сравнения: BGR, 3x48x320, padding справа.
Изображения передаются пакетами; вся книга в память не загружается.

Подключение подготовлено без установки зависимостей и без запуска распознавания.


### ZIP с дообученными OCR-весами

Вместо распакованных папок можно хранить:

- `models/finetuned_paddle_v5_headers_v2.zip`;
- `models/finetuned_paddle_v5_values_v2.zip`.

В архиве должны лежать рядом `best_model.pdparams`, `inference_config.yaml` и

одна папка комплекта внутри. Можно добавить last_model, историю и метрики.
