# Проверка трудных ячеек value в CVAT

Скрипт размещаем в `tools/dataset/export_ocr_values_to_cvat.py`. Это отдельный инструмент подготовки разметки, основной pipeline не меняется. Нужны Python 3.11+ и имеющиеся зависимости проекта. Используйте только собственные доверенные checkpoints.

Запуск из `D:\projects\ussr-ocr-table`:

```powershell
.\.venv\Scripts\python.exe .\tools\dataset\export_ocr_values_to_cvat.py ".\outputs\1953_F1562_Op11_D4479_ячмень\checkpoints\ocr.pkl"
```

Название книги берётся из `document_name` объектов checkpoint. Исходные страницы берутся из `data/processed/<книга>.zip`, проверяется контрольная сумма. Модели не загружаются, OCR повторно не запускается.

По умолчанию пакет сохраняется в `data/annotation/cvat/<книга>/ocr_value/exports/`. Для исправленных экспортов используйте соседнюю папку `reviewed/`. Можно задать `--output-dir`, `--threshold 0.95` или `--limit 30` для небольшой пробной загрузки. Существующий ZIP не перезаписывается.

Отбираются только `value`, удовлетворяющие хотя бы одному условию: пустой `ocr_value`, отсутствующая/неконечная уверенность, уверенность ниже порога или статус `needs_review`. Причины могут пересекаться. Низкая уверенность не доказывает ошибку; правильный результат тоже можно подтвердить вручную.

В ZIP находятся:

- `images/*.png` — отдельные ячейки без ресайза и нарисованных рамок;
- `annotations.xml` — формат CVAT for images, тег `value_text` на каждую ячейку;
- `project_labels.json` — полная схема класса и его текстовых полей;
- `manifest.json` — связь изображений с книгой, страницей, cell_id, bbox и исходным OCR.

## Загрузка в CVAT

1. Создайте отдельный проект, например `USSR Cargo — OCR value`. Не используйте проект bbox-детекции.
2. Распакуйте из ZIP `project_labels.json`. Откройте его как текст и скопируйте содержимое в редактор меток **Raw** при создании проекта. Сохраните. Должен появиться класс `value_text` типа Tag с пятью атрибутами. Это важно: импорт проекта сам по себе может создать названия классов, но не полную схему атрибутов.
3. Откройте проект → **Actions → Import dataset**, выберите **CVAT for images 1.1** (название может отображаться как CVAT for images), загрузите исходный ZIP целиком.
4. Откройте задачу и Job. Каждое изображение — одна вырезанная ячейка. Текст хранится в атрибутах тега `value_text`, а не в bbox. Откройте атрибуты тега в правой панели.
5. Исправьте `transcription` и установите `review_status = reviewed`. Если текст уже верен, подтвердите его тем же статусом. `model_prediction` оставляйте как исходную подсказку. `confidence` и `selection_reason` — информация отбора, не оценка ручной разметки.
6. Для неразборчивого текста выберите `unreadable`. Если crop обрезает символы, содержит чужие ячейки или ошибочно помечен как value — `bad_crop`. Не угадывайте ответ.
7. Нажмите **Save**, затем экспортируйте в **CVAT for images 1.1**, можно без изображений. Сохраните ZIP в `reviewed`. Не экспортируйте в YOLO: он не сохраняет нужные текстовые атрибуты.

`pending` означает, что пример ещё не проверен. В будущий обучающий TXT должны попадать только подтверждённые `reviewed`; автоматический экспорт здесь намеренно не создаёт train.txt из предсказаний.

Подпись — ровно видимый текст: сохраняйте запятые, точки, ведущие нули и знаки. `ocr_value` используется вместо `recognized_value`, поскольку последнее уже могло быть преобразовано в число. Многострочные ячейки нужно рассмотреть отдельно перед обучением обычного построчного распознавателя.

В этом пакете геометрия берётся из исходного `ocr.pkl`. Исправленные в CVAT bbox сюда автоматически не подмешиваются: номера объектов CVAT не гарантируют совпадения с исходными cell_id. Для новых bbox нужен отдельный шаг согласования.

Формат CVAT: https://docs.cvat.ai/docs/dataset_management/formats/format-cvat/
