# Детекция оставшихся книг и подготовка CVAT

Запуск из PowerShell в корне проекта:

```powershell
cd D:\projects\ussr-ocr-table
powershell -ExecutionPolicy Bypass -File .\prepare_cells_cvat_books.ps1
```

Скрипт использует Python `.venv\Scripts\python.exe`, три дообученные YOLO-модели
и входные ZIP из `data/processed`. Ничего не устанавливает и не скачивает.
По умолчанию работает на CPU. Для GPU с поддерживаемым PyTorch:

```powershell
.\prepare_cells_cvat_books.ps1 -Device 0
```

При недостатке памяти уменьшите `-BatchSize`, например до 1.
Другой Python можно указать через `-Python "полный\путь\python.exe"`.
В выбранной среде должны быть зависимости YOLO из requirements проекта.

## Какие книги обрабатываются

1. `1942_F1562_Op11_D1250_рудостойка_и_крепежный_лес`
2. `1942_F1562_Op11_D1254_обувь`
3. `1946_F1562_Op11_D2131_смазочные_масла`
4. `1946_F1562_Op11_D2140_флюсы`
5. `1953_F1562_Op11_D4471_серный_колчедан`
6. `1953_F1562_Op11_D4472_чёрные_металлы`
7. `1953_F1562_Op11_D4484_макрорегионы`

Для одной книги используйте, например:

```powershell
.\prepare_cells_cvat_books.ps1 -Books '1942_F1562_Op11_D1254_обувь'
```

## Какие модели и настройки используются

- `models/yolo_cell_detection_headers_v2.zip`
- `models/yolo_cell_detection_value_v2.zip`
- `models/yolo_empty_cell_detection_v2.zip`

В каждом архиве загружается `best_model.pt`.
Параметры берутся из `models/config_models_det.yaml`; имена архивов заменяются
на перечисленные выше в конфигурации запуска, исходный YAML не перезаписывается.
Устройство, batch size и порог уверенности задаются параметрами скрипта.
По умолчанию порог уверенности 0.25. Можно передать `-Confidence 0.2`.

Используются функции из `src/detection.py`: перекрывающиеся патчи, перевод bbox
на страницу, NMS и устранение конфликтов. Три модели загружаются один раз для всех книг.
В памяти находится одна страница и текущие batch патчей, а не все изображения книг.
Сохраняются все страницы, в том числе без обнаружений. Результаты — предсказания
для ручной проверки, а не гарантированно полная/верная разметка.

## Результат и импорт в CVAT

Для каждой книги создаётся отдельный архив:

```text
data/annotation/cvat/<книга>/cells_detection/exports/
    <книга>_cells_detection_yolo_v1_cvat.zip
```

Архив содержит полные изображения страниц и bbox четырёх классов:
`column_header`, `row_header`, `value`, `empty`.
Формат импорта разметки: **Ultralytics YOLO Detection 1.0**.
Изображения находятся в `images/train/`, метки — в `labels/train/`;
`data.yaml` и `train.txt` задают схему архива.
`train` здесь — имя каталога формата CVAT, а не назначение страниц в обучающий split.
При создании задачи используйте изображения из архива, затем импортируйте
разметку ZIP в указанном формате. Имена изображений должны совпадать.
OCR и заполнение transcription не выполняются.

Проверенная разметка обуви и остальные существующие выгрузки не перезаписываются.
После проверки в CVAT выгрузите исправленную разметку в `cells_detection/reviewed`.
Подготовку обучающих патчей выполняйте отдельно после ручной проверки.

## Повторный запуск

Checkpoint и сведения об использованных весах сохраняются в:

```text
outputs/<книга>/cells_detection_yolo_v1/
```

Checkpoint обновляется после каждой страницы. После остановки повторите ту же
команду: готовые страницы будут взяты из checkpoint, а готовые архивы пропущены.
Источник, версии моделей, настройки и код сверяются по контрольным суммам.
При их изменении используйте новое имя запуска, например:

```powershell
.\prepare_cells_cvat_books.ps1 -RunName cells_detection_yolo_v2
```

Существующий файл не перезаписывается. После аварийного завершения процесса
может остаться `outputs/<книга>/<RunName>/.pipeline.lock`; удалять его можно,
только убедившись, что соответствующий процесс уже остановлен.

Для отдельной проверки файлов и входов без запуска моделей:

```powershell
.\prepare_cells_cvat_books.ps1 -Preflight
```

Детекция и тесты при подготовке скрипта не запускались.
