# Сборка датасета PaddleOCR для value

Скрипт: `tools/dataset/build_paddle_value_dataset.py`. Не меняет pipeline, исходные архивы и статусы в CVAT. Требует Python и OpenCV/NumPy из существующего окружения проекта.

Берёт исправленную разметку из всех ZIP в `ocr_value/reviewed`, а изображения и сведения об исходной странице — из manifest.json и images в соседней `ocr_value/exports`. Исправленные строки берутся только из transcription. Предсказания модели не используются как правильные ответы.

Пример запуска из `D:\projects\ussr-ocr-table`:

```powershell
.\.venv\Scripts\python.exe .\tools\dataset\build_paddle_value_dataset.py `
  '.\data\annotation\cvat\1953_F1562_Op11_D4479_ячмень\ocr_value\reviewed' `
  --confirm-pending `
  --dictionary '.\models\pretrained\cyrillic_PP-OCRv5_mobile_rec\ppocrv5_cyrillic_dict.txt'
```

`--confirm-pending` используем здесь, потому что пользователь подтвердил полную ручную проверку 972 уверенных ячеек. Без этого параметра включаются только явные reviewed. bad_crop и unreadable исключаются всегда. Исходные ZIP не переписываются, подтверждение pending фиксируется в manifest.json готового датасета.

По умолчанию вывод: `data/training/paddle_value/v1/`:

```text
images/
train.txt
val.txt
manifest.json
```

TXT содержит путь относительно корня датасета, табуляцию и точный исправленный текст. Этот корень нужно указать в data_dir конфигурации PaddleOCR. Пробелы и пунктуация сохраняются. Пустые, многострочные подписи и символы вне явно указанного словаря вызывают ошибку, чтобы их можно было проверить вручную.

По умолчанию 20% исходных страниц выделяется под валидацию с seed=42. Все ячейки одной страницы попадают только в одну часть. Количество ячеек в train/val не обязано совпадать с 80/20 точно. Разделение содержит и трудные, и уверенные ячейки; их количество записывается в manifest. Отдельного независимого test пока нет: val используется для выбора модели, поэтому итоговую проверку позже нужно провести на отдельной книге или отложенных страницах.

Padding по умолчанию 0. Для отдельного варианта укажите `--padding 4 --output-dir '.\data\training\paddle_value\v1_pad4'`. Рамка добавляется с каждой стороны, цвет — медианный цвет пикселей исходной ячейки. Символы не масштабируются. При использовании варианта с padding такую же подготовку нужно применять в inference и сравнить качество с исходными картинками. Случайные аугментации настраиваются позже только для train.

Скрипт не перезаписывает существующую версию. Если в reviewed лежат конфликтующие экспорты одной картинки, сборка останавливается: нужно выбрать одну актуальную версию. Одинаковые повторы объединяются. Имена, исходные предсказания, размеры картинок и отсутствие повторов исходной ячейки проверяются.

После успешной сборки сохраняйте весь каталог версии. Проверенные подписи и manifests — данные; не включайте большие архивы/изображения в Git без принятого в проекте решения.
